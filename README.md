# Telegram browser agent — Gemini Web + API (Bothost)

Личный Telegram-агент для **одного владельца и только личного чата**. Модель планирует шаги; отдельный Playwright/Chromium открывает сайты, читает видимые элементы, заполняет поля, делает скриншоты, загружает и скачивает файлы. Есть shell, Python/Node и операции с файлами внутри контейнера.

**Antigravity CLI, OAuth-форма, Linux keyring и их зависимости удалены.** Google-аккаунт подключается к **веб-интерфейсу Gemini** через приватный cookie-файл на хосте. OpenAI-совместимый API-режим сохранён.

> Браузерная интеграция экспериментальная: это автоматизация видимого интерфейса, не официальный API Gemini. Живой вход в Google, доступ к Argon и deployment на вашем Bothost **не проверены**. Cookie-файл не отменяет региональные ограничения, квоты, подписку, CAPTCHA/2FA или политику Google. Не рассчитывайте, что замена Antigravity сама по себе решит доступ из России. Используйте только свои сессии и соблюдайте правила сервисов.

## Что реализовано

- Два **раздельных профиля** Chromium: приватный провайдер Gemini и рабочий браузер агента. Оба вне `workspace`.
- Gemini возвращает JSON: финальный ответ либо один запрос инструмента. Никаких скрытых Gemini RPC, поддельных model ID, автообхода проверок или незаметного переключения на другую модель.
- Выбор **точной доступной подписи модели** и **силы/уровня рассуждений**, если такое меню есть в вашем интерфейсе. Отсутствующая настройка = ошибка, не запасная модель.
- По умолчанию **40 шагов на сообщение**, `/steps 1..200` меняет лимит; `/continue` продолжает по сохранённой цели и последним результатам. По умолчанию до 30 минут на этап; каждый вызов модели до 180 секунд. Это лимиты, не гарантии качества/полноты.
- `/screen` присылает скриншот **текущего рабочего браузера**, в том числе во время задачи. «Сделай скрин и отправь» работает через инструменты модели. Вкладка остаётся открытой между сообщениями; после рестарта сохраняются cookies профиля, но не обещается восстановление незавершённой навигации/страницы.
- `/secret текст`: одноразовое значение для поля браузера, без передачи значения модели. Подробности и ограничения ниже.

## Установка на Bothost

1. Создай бота в `@BotFather`. Токен введи **только в настройках хостинга**, не в GitHub и не в переписку с AI.
2. Загрузи архив исходников или подключи Git-ветку. Главный файл `main.py`; **обязательно собственный Dockerfile**. Для двух Chromium-процессов рекомендуем не менее 2 ГБ RAM; реальное потребление зависит от страниц и модели.
3. Укажи `TELEGRAM_OWNER_ID` — твой числовой Telegram user ID, не ID аккаунта Bothost. Без него бот не запустится. Хост передаёт `BOT_TOKEN` / `TELEGRAM_BOT_TOKEN` автоматически.
4. Постоянный каталог: `/app/data`. Укажи переменные из `.env.example` в панели, не публикуй настоящий `.env`.
5. **Пересобери контейнер**, не просто перезапусти: удалены старые зависимости и изменены требования Playwright.
6. При необходимости `/health` на внутреннем `PORT=8080`. Публичный домен и `PUBLIC_URL` для входа больше не нужны; старые `/login` и `/auth/*` HTTP endpoints возвращают 404. `/login` в Telegram теперь только инструкция.

## Подключение cookies Gemini — только на хосте

Cookies предоставляют доступ к аккаунту. Лучше отдельный Google-аккаунт с минимальными данными, а не основной. Не отправляй сессионные cookies боту в Telegram, в issues/PR, в чат с AI или через `/secret`.

1. На своём устройстве войди в `https://gemini.google.com/app`, заверши необходимые подтверждения и проверь, что нужная модель действительно доступна.
2. Своим доверенным локальным инструментом экспортируй **cookies Google** в JSON. Поддерживается JSON-массив Cookie-Editor/Chrome или Playwright storage-state `{ "cookies": [...] }`. Включай только собственную сессию. Netscape TXT не поддерживается. `localStorage` и чужие домены не импортируются. Не устанавливай неизвестные расширения ради экспорта.
3. Через **защищённую панель файлов/секретов своего хоста** положи файл, например:
   `/app/data/secrets/gemini-cookies.json`. Не клади его в репозиторий, ZIP с кодом или `/app/data/workspace`.
4. Требования: обычный файл, не symlink; права **600**; владелец пользователя процесса контейнера (**UID 10001**); до 1 МБ. Каталог secrets — 700. Если панель не позволяет выставить владельца/права или смонтировать секрет, сначала уточни это у поддержки хостинга: не ослабляй проверки в коде.
5. В панели:
   - `GEMINI_COOKIES_FILE=/app/data/secrets/gemini-cookies.json`
   - `DEFAULT_MODE=web`
   - `GEMINI_WEB_MODEL=Gemini 4 Argon` **только если такое точное название есть у аккаунта**; иначе реальная подпись или `auto`.
   - `GEMINI_WEB_STRENGTH=auto` либо точная доступная подпись.
6. Перезапусти, `/mode web`, `/checklogin`. После замены cookie-файла `/checklogin` закрывает старую сессию и импортирует новый файл.
7. `/models` читает фактическое меню. `/model <подпись>` сохраняет выбор. `/strengths` читает меню силы после выбора модели; `/strength <подпись>` сохраняет выбор. Затем `/checklogin` проверяет **наличие поля чата и применение настроек, не генерацию**. Обычное «Привет» проверяет генерацию и может расходовать квоту.

`auto` означает «оставить выбор сайта», **не** «автоматически использовать Argon/максимальную силу». Бот не создаёт доступ к модели. Google описывает поэтапную доступность Gemini 4 Argon: [официальный анонс](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/).

Сохранённые настройки `state/settings.json` имеют приоритет над env. Менять модель/силу после настройки проще командами `/model` и `/strength`. Старый режим `agy`/`account` мигрирует в `web`; старый `account_model` удаляется. Старые каталоги keyring/home **не удаляются автоматически**, чтобы не уничтожить пользовательские данные; после резервного копирования можно удалить их вручную.

### Если интерфейс Gemini отличается

UI меняется; подписи локализованы и могут зависеть от аккаунта. По умолчанию используются видимые role-based элементы и `model-response .markdown`. При неоднозначности бот останавливается. На своём хосте после осмотра DOM можно задать:

- `GEMINI_INPUT_SELECTOR`
- `GEMINI_MODEL_BUTTON_SELECTOR`
- `GEMINI_STRENGTH_BUTTON_SELECTOR`
- `GEMINI_RESPONSE_SELECTOR`

Меню должно иметь видимые элементы с `role=menuitem`, `menuitemradio` или `option`; подпись выбора проверяется через кнопку/ARIA-state. Не придумывай селектор вслепую. Если интерфейс/роль изменились существенно — нужен патч адаптера. Наличие настроек «силы» у конкретного аккаунта **не гарантируется**. Никакой подмены реального уровня фразой в prompt нет.

## Команды

| Команда | Действие |
|---|---|
| `/start`, `/help` | Справка |
| `/setup` | API или Gemini Web; модель и сила |
| `/login` | Инструкция для cookie-файла на хосте, не OAuth |
| `/checklogin` | Перечитать cookies; проверить UI и выбор, без генерации |
| `/mode api`, `/mode web` | Режим; очистка истории/цели |
| `/models` | API model IDs или подписи меню Gemini |
| `/model Gemini 4 Argon` | Запросить точную веб-модель, если доступна |
| `/strengths` | Доступные подписи меню силы |
| `/strength High` | Пример: выбрать точную подпись; `auto` — выбор сайта |
| `/steps 80` | Лимит шагов, диапазон 1–200 |
| `/continue` | Продолжить сохранённую задачу; сделанное не повторять |
| `/screen` | Скриншот текущего рабочего браузера |
| `/secret текст` | Секрет для одноразового заполнения поля |
| `/secret clear` | Очистить секреты из памяти |
| `/status` | Состояние без cookies/ключей |
| `/stop` | Остановить задачу, не отменяет сделанное |
| `/new` | Очистить историю и цель, не файлы/браузер |
| `/cancel` | Отменить мастер настройки, не задачу |

Пример: «Открой example.com, прочитай страницу, сделай скриншот и пришли». Для большой задачи `/steps 80`, при достижении лимита `/continue`. Остановка процесса не откатывает отправку форм, сообщения или изменения файлов. Не проси агента нарушать правила сайтов или выдавать выполнение за самостоятельную работу человека.

## `/secret`: что это защищает и чего не защищает

**Telegram-боты не поддерживают сквозное шифрование.** `/secret пароль` — удобство для исключения значения из модельного prompt/истории, а не безопасный канал на уровне Signal/Secret Chat. Telegram, клиент, инфраструктура и администратор хоста могут иметь доступ. Бот запрашивает удаление сообщения; не гарантируется уничтожение всех копий. Если удаление не удалось, сообщает об этом.

- Только владелец, в личном чате. Значение до 4096 символов; максимум 20 секретов.
- Хранение в памяти процесса на **15 минут**, без записи в конфиг, history, goal или файл. Перезапуск теряет секреты. Это не защищённое аппаратное хранилище и не гарантия обнуления памяти/дампов.
- Бот отвечает случайным ID `s_…`. Далее обычной задачей: «Введи секрет s_… в поле пароля на текущем сайте»; для последнего неиспользованного секрета можно `latest`.
- Модель передаёт только `browser(action="fill_secret", selector="наблюдаемый селектор", secret_id="s_…")`. Host-процесс заполняет поле; значение не возвращается инструментом. Подтверждение действия содержит только ссылку, не значение.
- После успешного заполнения повторное использование запрещено. Значение остаётся в памяти **только для маскирования текстового вывода до истечения тех же 15 минут**, затем удаляется; `/secret clear` удаляет сразу. Маскирование best-effort: не распознаёт преобразования/кодирование; после истечения/очистки уже отражённое сайтом значение больше не известно маскировщику.
- Скриншот может показать введённые данные, если сайт их не маскирует; `/screen` отправляет его только владельцу. На принимающем сайте данные видны этому сайту. Не выполняется автоматическая отправка формы только из-за `/secret`.
- Shell/код работает тем же Unix-пользователем, что и бот: это **не жёсткая изоляция от модели/процессов**, только раздельный интерфейс ввода. Не одобряй shell-команды, чтение профилей, дампы памяти или отправку архивов, если не понимаешь их. Для чувствительных сессий используй изолированный аккаунт/контейнер.
- Google cookies провайдера подключай **только на хосте**, не через эту команду.

## API-режим

`/setup → API + KEY + MODEL`: OpenAI-совместимый HTTPS URL, ключ, точный model ID. Либо `API_BASE_URL`, `API_KEY`, `API_MODEL` в панели хостинга, затем `/mode api`. `/setup` имеет приоритет над env. Ключ Gemini: https://aistudio.google.com/apikey . Аккаунт Gemini Web и API имеют отдельные квоты/доступ.

Для API-режима поддержан vision у совместимых моделей. **Gemini Web в этой сборке получает только текст**, без прямого прикрепления картинок/файлов. Рабочий браузер умеет сделать/отправить скриншот; это не значит, что Web-модель его видит. Не обещаются генерация изображений, OCR сканов или speech-to-text.

## Данные и безопасность

- `workspace/`: загруженные/созданные файлы; `state/`: конфиг, история, цель, `gemini-profile/`, `task-browser-profile/`; `secrets/`: host-managed cookies. Не публикуй ни один из этих каталогов. Профили вне workspace — защита от случайного доступа file tools, **не от shell того же UID**.
- `CONFIRM_TOOLS=on` по умолчанию: каждый tool-call подтверждается владельцем до 180 секунд. `/screen` — прямой явный запрос владельца, без второго подтверждения. `off` делает инструменты автономными и повышает риск внешних действий/удалений. Не выключай подтверждения для недоверенных сайтов/файлов.
- Бот работает не root; Docker socket/host home не монтировать. Контейнер не полноценная security boundary. Сеть не ограничена allowlist: приватные адреса тоже могут быть доступны. Для production нужны изоляция и сетевые правила хоста.
- Файловые инструменты запрещают выход за workspace, но shell выполняет разрешённый владельцем код, не является sandbox и может читать другие файлы процесса. ENV-секреты не наследуются в shell, однако это не защита от чтения файлов/памяти.
- История до 24 сообщений на диске, контекст до 32 сообщений; актуальная цель хранится отдельно. Очень длинный контекст сокращается по целым сообщениям. Для слишком длинного последнего сообщения запрос отклоняется, а не тихо обрезается.
- Ответы/ошибки Gemini не публикуют raw Playwright diagnostics, URLs входа или cookies. JSON неполного ответа не исполняется. Это не независимый аудит безопасности.
- Страницы/документы — недоверенные данные: проверяй запросы на отправку форм, shell, загрузку и скачивание.

## Проверки

См. `QA.md`. Основные тесты:

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m compileall -q agent main.py tests
```

Локальные UI/Chromium smoke-тесты (без настоящего Google/Telegram аккаунта):

```bash
playwright install --with-deps chromium
RUN_BROWSER_TESTS=1 python -m unittest discover -s tests -p test_browser_smoke.py -v
```

При использовании системного Chromium можно задать `CHROMIUM_EXECUTABLE=/usr/bin/chromium`. В Gemini-провайдере штатно используется Playwright Chromium; переменная предназначена для рабочего браузера/локальных smoke-тестов.
