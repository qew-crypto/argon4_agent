# Telegram Agent для Bothost — API + официальный Antigravity CLI

**Эта версия предназначена для Bothost.ru, не требует работы пользователя в терминале.** Загрузка ZIP через панель → токен и Telegram ID в настройках → дальнейшая настройка из бота.

Два режима:
- OpenAI-совместимый API: URL + KEY + MODEL через `/setup`.
- Google-аккаунт: официальный Antigravity CLI (`agy`), `/login` открывает HTTPS-форму для официального Google OAuth.

## Установка через панель (без команд)

1. Создай Telegram-бота в официальном `@BotFather` через `/newbot`; сохрани токен. Не присылай его в чат с AI.
2. Войди на https://bothost.ru . Для загрузки ZIP нужен Базовый или Pro. Для браузера и CLI рекомендуем Pro (2 ГБ RAM); реальное потребление зависит от задачи.
3. Если кнопки **«Загрузить из архива»** нет, включи в настройках аккаунта функцию загрузки архивов (Bothost относит её к бета-интерфейсу).
4. **Мои боты → Загрузить из архива** → выбери `telegram-bothost-agent.zip`.
5. Введи название и токен от BotFather. Главный файл: **`main.py`**. Язык: Python. В дополнительных настройках обязательно включи **«Использовать собственный Dockerfile»**: нужны Chromium, Antigravity и Linux keyring.
6. В **переменных окружения** добавь **`TELEGRAM_OWNER_ID` = твой числовой Telegram user ID**. Узнать его можно через доверенный Telegram-инструмент (например, @userinfobot). `USER_ID` от Bothost — ID пользователя платформы, не подставляй его вместо Telegram ID.
7. Для входа Google подключи **HTTPS-домен** бота в Bothost и **внутренний порт `8080`**. Добавь `PORT=8080`. Добавь `PUBLIC_URL=https://твой-домен` без пути в конце. Если Bothost корректно передаёт `DOMAIN`, URL определится автоматически, но явная настройка предпочтительнее.
8. Нажми **«Задеплоить»**. Дождись завершения сборки; Chromium и системные пакеты могут собираться несколько минут. При необходимости нажми «Перезапустить/Пересобрать» после изменения переменных/домена.
9. Открой своего Telegram-бота, нажми **Start**, отправь `/start`.

**Токен** Bothost передаёт автоматически как `BOT_TOKEN` / `TELEGRAM_BOT_TOKEN`. Вносить его второй раз в исходники не нужно. Без Telegram owner ID бот откажется запускаться — это намеренная защита от захвата первым посторонним.

Для API-режима домен не обязателен; для `/login` обязательно HTTPS. Telegram polling не требует webhook; домен здесь обслуживает форму входа и `/health`.

## Google-аккаунт — без терминала

1. Отправь боту **`/login`**.
2. Нажми **«Подключить Google»**. Откроется форма на HTTPS-домене твоего бота, действующая **10 минут**. Не пересылай эту ссылку.
3. Дождись кнопки **«Открыть официальный вход Google»**.
4. Авторизуйся на **`accounts.google.com`** со своего устройства. Пароль вводится только Google, не боту/форме Bothost.
5. Google/официальный flow покажет одноразовый код возврата. Вернись в форму своего бота, вставь код в поле и нажми **«Подключить»**. Не отправляй код сообщением в Telegram.
6. Дождись результата проверки. На успехе режим **Antigravity** включится автоматически. Проверка делает один короткий запрос к модели и может расходовать квоту/стоить денег по условиям аккаунта.
7. Вернись в Telegram: **`/status`**, **`/models`**, затем обычное сообщение, например «Привет».
8. При необходимости **`/setup` → Google / Antigravity → точный model ID**, либо `auto`, чтобы CLI выбирал свою доступную модель.

В текущей тестовой среде проверены установка официального CLI, экран выбора Google, извлечение официальной OAuth-ссылки и отмена процесса. **Полный вход с настоящим аккаунтом и persistence keyring на контейнере Bothost НЕ проверены.** `/login` — экспериментальная интеграция с интерактивным CLI, его UI может меняться. Это не обещание гарантированного входа на любом тарифе.

Если форма говорит «код отправлен, но пробный запрос не прошёл», причина может быть в коде, сохранении keyring, квотах, сети или доступе. Вход не объявляется успешным без успешного запроса модели. Используй `/cancel`, затем попробуй `/login` снова. Если CLI уже видит сохранённую сессию, форма предложит `/mode agy`; проверь её обычным сообщением.

Сбой D-Bus/keyring больше не останавливает Telegram-бота: API-режим доступен независимо, а `/login` показывает диагностику и повторяет запуск keyring. D-Bus использует отдельный приватный Unix-сокет и runtime-каталог, а не унаследованный root/host session bus.

Для работы keyring контейнер устанавливает D-Bus и GNOME Keyring. Он запускается под отдельным непривилегированным UID. Профиль Google хранится в домашней папке внутри `/app/data/home`, keyring разблокируется локальным случайным секретом из файла с правами 600. Это защита правами доступа на сервере, а **не независимое шифрование от владельца/администратора сервера**.

## API URL + KEY + MODEL — через бота

1. `/setup` → **API + KEY + MODEL**.
2. Отправь `default` для Gemini или HTTPS base URL другого OpenAI-совместимого сервиса.
3. Введи API-ключ; бот попытается удалить сообщение. **Telegram-боты не имеют сквозного шифрования**, удаление не уничтожает гарантированно все копии. Более безопасная альтернатива — передать `API_KEY` и `API_MODEL` в переменных Bothost; не публикуй их в исходниках.
4. Введи точный ID модели. Если он неизвестен, можно сохранить временное имя, вызвать `/models`, затем повторить `/setup` с настоящим ID.
5. `/models` показывает список у настроенного провайдера. Поддержка зависит от провайдера.

Ключ Gemini: https://aistudio.google.com/apikey . API-подписки и аккаунтные квоты могут различаться. API не использует web cookies.

`/setup` сохраняет настройки с приоритетом над переменными окружения. При изменении только переменных ключ может остаться старым — тогда обнови его через `/setup`.

## Gemini 4 Argon

Официальное имя — **Gemini 4 Argon**. Анонс описывает поэтапный доступ, вначале доверенные пользователи и затем расширение для платных API-клиентов и Google AI Ultra.

Бот не обходит ограничения. Ни подписка, ни видимость модели в web Gemini не гарантируют её доступность в Antigravity/API. Точный ID не придуман: используй модель, реально доступную через `/models` или предоставленную Google. В режиме `auto` CLI не обещает выбирать Argon.

## Возможности и команды

- Приём документов и изображений в `workspace/uploads`, отправка файлов/фото/архивов.
- Bash/shell внутри контейнера, Python и Node; не root-доступ ко всему Bothost.
- Chromium: открывать страницы, читать текст/контролы, кликать, заполнять поля, screenshots, upload/download. Cookies сохраняются в `workspace/browser-profile`.
- Текстовые файлы, извлечение текста до 20 страниц PDF, ZIP-архивы.
- В API-режиме — анализ изображения при поддержке vision моделью. **Прямой vision в аккаунтном режиме Antigravity не реализован**. Сохранение/отправка изображений доступны в обоих режимах.
- Генерация изображений через отдельный model endpoint не реализована. Можно отправить существующий файл, скриншот или результат скрипта.

| Команда | Назначение |
|---|---|
| `/start`, `/help` | Справка |
| `/setup` | Режим, URL, ключ, модель |
| `/login` | Вход Google через Antigravity и HTTPS-форму |
| `/cancel` | Отменить мастер/ожидающий вход |
| `/mode api`, `/mode agy` | Переключить режим, очистить историю |
| `/models` | Модели текущего провайдера |
| `/status` | Статус без секретов |
| `/new` | Очистить историю, не рабочие файлы |
| `/stop` | Остановить текущую модельную задачу; сделанное не отменяется |

Примеры: «Открой example.com, сделай скриншот и отправь», «Создай скрипт и отправь результат файлом», «Прочитай приложенный PDF», «Собери output в ZIP и отправь».

## Данные и обновления

Все рабочие данные находятся **в `/app/data`**:
- `workspace/`: файлы и browser cookies;
- `state/`: настройки API и ограниченная история;
- `home/`: профили Antigravity/Google и Linux keyring.

Bothost сохраняет `/app/data` при обновлении архивного бота. Чтобы обновить код, на карточке бота нажми загрузку нового архива; token/env/domain сохраняются. Для Git в будущем можно создать Git deployment с теми же исходниками; миграция сохранённых данных между разными ботами должна быть отдельной операцией.

Не публикуй `.env`, `data/`, tokens, browser profiles и Google credentials. В репозиторий добавлены исключения `.gitignore`. Git-репозиторий должен содержать только исходники, без настроек аккаунтов и рабочих данных.

## Безопасность и ограничения

- Только один разрешённый Telegram user ID, только личный чат. Группы/посторонние игнорируются.
- `CONFIRM_TOOLS=on` по умолчанию: собственные инструменты бота требуют подтверждения кнопкой (180 сек). Проверяй shell-команды, URL и отправляемые файлы, особенно удаления/внешние действия. `off` — автономный режим с соответствующим риском.
- Antigravity запускается с `--mode plan`, без `--dangerously-skip-permissions`; prompt просит возвращать запросы инструментов как JSON. **Это не жёсткая изоляция всех встроенных tools CLI**: CLI может иметь собственные read/planning tools. Отдельный permission broker для нативных tools не реализован.
- Бот не root после запуска. Bothost управляет контейнером; shell не даёт доступа к хосту и Docker socket. Не монтировать домашние директории/SSH keys и не включать privileged mode.
- API-ключ хранится в `state/settings.json` как plaintext с правами 600. Shell и бот работают одним UID и могут теоретически читать Google/ключи внутри контейнера. Не давай модели широких разрешений для недоверенных документов.
- OAuth-код не передаётся в чат с моделью/Telegram и не сохраняется приложением. Raw terminal не публикуется в веб-форме; нет возможности выполнить произвольный ввод/команды через web endpoints.
- Ссылка формы — короткоживущая capability. Она приходит через Telegram (не E2E), поэтому не пересылай её. Токен передаётся в URL fragment (не в query), затем в HTTPS Authorization header. Хостинг-администратор имеет доступ к серверу; защита от администратора не заявляется.
- Form endpoints проверяют capability, Origin и HTTPS proxy header. Bothost reverse proxy должен передавать `X-Forwarded-Proto: https`. Если форма получает «запрос отклонён» даже по правильной ссылке, это нужно выяснить с поддержкой Bothost; не отключать HTTPS проверку ради обхода.
- Домен должен вести именно на этот контейнер и совпадать с PUBLIC_URL. Приложение слушает `0.0.0.0:$PORT`, `/health` проверяет только процесс, не доступ Google/Telegram.
- Сеть внутри контейнера не ограничена allowlist; внутренние сервисы теоретически доступны. Docker не абсолютная security boundary.
- История 24 сообщения, во время задачи не более 32 последних сообщений для модели. По умолчанию 12 tool-steps; «продолжай» запускает следующий этап. Модель 180 сек, shell 90 сек.
- По умолчанию загрузка 20 МБ, отправка 49 МБ. Telegram имеет свои ограничения. Фото >9 МБ отправляются документом.
- Архивы не распаковываются и файлы не запускаются автоматически. Проверяй пути при распаковке/выполнении через shell.
- OCR сканов, speech-to-text, многопользовательский режим и потоковые ответы не реализованы. Некоторые browser logins/CAPTCHA/passkeys требуют отдельного решения.
- CLI/UI и зависимости изменяются; installer скачивает актуальный официальный agy. Для стабильного production закрепи проверенную версию после тестирования. API/аккаунтные квоты и лицензии провайдера действуют независимо от бота.

## Если не работает

- `KEYRING_UNAVAILABLE`: API-режим продолжает работать. Для Google проверь собственный Dockerfile и текст диагностики; ошибка keyring больше не вызывает рестарт всего бота.
- Не стартует: проверь в панели токен, `TELEGRAM_OWNER_ID`, main.py, собственный Dockerfile и логи старта.
- Killed/137: память; браузер/CLI могут не помещаться в тариф.
- 502: HTTPS-domain/internal port должен совпадать с `PORT` (8080).
- Нет кнопки загрузки: настройка архива/тариф в Bothost.
- `/login` не даёт ссылку: проверь domain/PUBLIC_URL и пересоздай deployment после изменений.
- Google entry не завершён: отмена `/cancel`, новый `/login`; полный screenshot ошибки можно отправить без одноразового кода, токенов и URL формы.
- После входа модель не отвечает: `/status`, `/models`; проверь доступ модели и квоты. Не считать это доказательством доступности Argon.
